# Тетрадь с пометками

Сайт для преподавателя английского и его учеников.

- Преподаватель создаёт задания и выдаёт их всем ученикам или отмеченным. На странице задания видно, кто сдал, а кто нет; задание можно изменить, а удалить, только пока его никто не сдал.
- Ученик сдаёт ответ текстом.
- Преподаватель выделяет ошибку в тексте, выбирает тему (времена, артикли, предлоги…) и пишет комментарий, потом возвращает работу на исправление или принимает её.
- Ученик видит подчёркнутые ошибки, пишет исправление к каждой и отправляет обратно.
- У ученика и преподавателя есть сводка «темы для повторения»: сколько ошибок по каждой теме во всех работах. У преподавателя есть страница каждого ученика со всеми его заданиями.
- Список тем преподаватель редактирует на странице «Темы ошибок».

Статусы работы: **Сдано → На исправлении → Исправлено → … → Принято**.

Стек: Next.js 16 (App Router, Server Actions), Supabase (Postgres, вход, Row Level Security), хостинг на Vercel.

## Запуск

### 1. База в Supabase

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатного тарифа хватает).
2. Откройте **SQL Editor** и по очереди выполните файлы из `supabase/migrations/` по порядку номеров (`0001_…`, `0002_…`, `0003_…`): вставьте содержимое и нажмите **Run**.
3. Для теста отключите подтверждение почты: **Authentication → Sign In / Providers → Email → Confirm email** выключить. Иначе после регистрации придётся подтверждать адрес по письму, а у встроенной почты Supabase низкий лимит писем в час. Названия пунктов меню у Supabase иногда меняются.

### 2. Ключи

Скопируйте `.env.example` в `.env.local` и заполните значения из **Project Settings → API Keys** (или кнопки **Connect** в шапке проекта):

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

Подойдёт и старый `anon` ключ. Секретный ключ (`service_role` / `sb_secret_...`) сюда не нужен и не должен сюда попадать.

### 3. Локальный запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

### 4. Назначить преподавателя

Каждый новый аккаунт становится учеником. Зарегистрируйте два аккаунта (преподаватель и ученик), затем в SQL Editor выполните:

```sql
update public.profiles set role = 'teacher' where email = 'почта-преподавателя@example.com';
```

### 5. Публикация на Vercel

1. На [vercel.com](https://vercel.com) нажмите **Add New → Project** и выберите этот репозиторий.
2. В **Environment Variables** добавьте те же две переменные.
3. **Deploy**. Адрес сайта можно отправить ученику.

## Проверки

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run test:db   # нужен Postgres 16, см. ниже
```

Те же проверки автоматически запускаются на GitHub при каждом PR (`.github/workflows/ci.yml`).

### Проверка прав в базе

Права (ученик видит только свои работы, не может сам принять работу, преподаватель не меняет текст ученика и т. д.) проверяются сценарием на обычном Postgres 16 с заглушкой Supabase:

```bash
PGHOST=localhost PGUSER=postgres npm run test:db
```

Скрипт пересоздаёт базу `homework_test`, применяет все миграции и прогоняет сценарий. Если какое-то правило нарушено, он остановится с ошибкой «ОЖИДАЛАСЬ ОШИБКА» или «НЕВЕРНО».

## Что пока не сделано

- Группы учеников (сейчас учеников отмечают по одному).
- Сдача файлом или фото тетради.
- Уведомления на почту о сдаче и проверке.
- Сроки считаются по московскому времени.
